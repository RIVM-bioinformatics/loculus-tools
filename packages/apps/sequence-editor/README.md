# Sequence Editor

A Rust-powered WebAssembly MSA (Multiple Sequence Alignment) engine for viral genome alignment editing, optimized for 60 FPS performance with instantaneous mutations.

> **Companion documents**
>
>
> - [`engine/engine-api.md`](./engine/engine-api.md) — JavaScript/TypeScript API reference for frontend developers
> - [`engine/engine.md`](./engine/engine.md) — internal implementation details and architecture for Rust developers

## Layout

- `engine/` — the Rust/WASM engine crate (`Cargo.toml`, `src/`).
- `wasm/` — the compiled WASM package, generated by `wasm-pack` and consumed by `frontend/` as a `workspace:*` dependency. Not committed to git except for `package.json`, which must exist for pnpm to resolve the workspace dependency on a fresh checkout.
- `frontend/` — the React/Vite app.

## Quick Start

### Prerequisites

- **Rust** (via [rustup](https://rustup.rs), 1.70+): [Install Rust](https://www.rust-lang.org/tools/install)
- **Node.js** (18+): [Install Node.js](https://nodejs.org/)
- **wasm-pack**: Install with `cargo install wasm-pack`

### Running the App

This package is part of the `loculus-tools` pnpm monorepo, so setup happens from the **repo root**, not from within this folder.

```bash
pnpm install
```

Run from the repo root, this installs all workspace dependencies and (via the root `postinstall` script) compiles the Rust engine to WebAssembly, outputting the compiled package to `wasm/`. The `wasm/package.json` file is checked in because pnpm must resolve the `workspace:*` dependency before `postinstall` can create the rest of the generated package. To rebuild the WASM module only, run `node scripts/build-wasm.mjs` from the repo root, or `wasm-pack build --target web --out-dir ../wasm` from the `engine/` directory directly.

1. **Start the development server**:

```bash
pnpm --filter @rivm-loculus-tools/sequence-editor start
```

The app will be available at `http://localhost:5173`.

### Building for Production

```bash
pnpm --filter @rivm-loculus-tools/sequence-editor build
```

The production-ready build will be in `frontend/dist/`.

## Architecture

The application uses a three-layer architecture:

- **Rust/WASM Engine** (`engine/src/lib.rs`): Manages the alignment matrix in memory, handles all mutations, parses FASTA input, and maintains undo/redo history. For implementation details, see [`engine/engine.md`](./engine/engine.md).
- **Web Worker Bridge** (`frontend/src/engine/`): Runs the WASM engine off the main thread via `postMessage` to prevent blocking UI interactions. Handles request/response serialization and buffer transfers.
- **React UI** (`frontend/src/`): High-level UI state management and controls. For the complete JavaScript/TypeScript API, see [`engine/engine-api.md`](./engine/engine-api.md).
- **Canvas Renderer** (planned): A 2D `<canvas>` renderer that paints the sliding-window viewport of the sequence grid at 60 FPS. This mirrors the viewport approach used in the test harness and is preferred over a WebGL pipeline for long-term maintainability.

> **For frontend developers:** Start with [`engine/engine-api.md`](./engine/engine-api.md) to learn how to interact with the engine through the `useEngineWorker()` hook.
>

> **For internal developers:** See [`engine/engine.md`](./engine/engine.md) for details on the Rust implementation, data structures, and how the WASM boundary works.
